# Tool plugin development

Tool plugins add focused in-app interfaces or separately hosted applications to
datalab. This section is the developer path; it covers creation, implementation,
testing, packaging, and distribution without requiring the API reference or
source code.

Start with [Developing tool plugins](tool-plugin.md). It owns the shared project
workflow, provider contract, route and permission model, selected-items actions,
tests, and release checklist. Then follow one UI-specific tutorial:

- [Developing an in-app tool plugin](in-app-tool-plugin.md) builds a Vue tool
  below datalab's navigation and calls the API through the frontend SDK.
- [Developing a standalone tool plugin](standalone-tool-plugin.md) opens in a
  separate tab and exchanges a one-use launch code for temporary API access.

Both tutorials use packages generated by the
[datalab tool plugin template](https://github.com/Matgenix/datalab-tool-plugin-template)
and have complete companion repositories:

- [in-app Hello World example](https://github.com/Matgenix/datalab-in-app-tool-plugin-example)
- [standalone Hello World example](https://github.com/Matgenix/datalab-standalone-tool-plugin-example)

For larger examples, see the
[item comparison tool](https://github.com/Matgenix/datalab-item-comparison-tool)
for an in-app selected-items workflow and
[`datalab-jupyter`](https://github.com/Matgenix/datalab-jupyter) for a standalone
service integration.

Tool plugins are trusted code. Provider Python runs in the datalab API process,
and an in-app bundle runs inside the signed-in datalab page. Design permission
checks, credential handling, dependencies, built assets, and release provenance
as part of the feature rather than as deployment afterthoughts.
